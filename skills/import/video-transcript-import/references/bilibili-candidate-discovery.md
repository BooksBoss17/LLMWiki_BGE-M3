# B站视频候选发现与反风控检索

当用户要求“看看某 UP 主以前/更早/漏网的视频”时，先做候选发现和筛选，不要直接下载导入。

## 触发场景

- 用户要求补抓某 UP 主早期视频、漏网视频、旧账号视频。
- B站 UP 投稿列表接口被风控，不能直接分页获取完整投稿。
- 需要区分：官方账号原创教学视频 vs 直播回放/搬运合集/学习规划/娱乐采访。

## 推荐流程

1. **先读本地已导入清单**：扫描 `raw/transcripts/<UP主>/`，提取已导入标题、BV号、三层文件、关键帧数量，形成去重基线。
2. **用已导入 BV 反查 UID**：调用 `video_detail(BV号)`，记录 `owner.mid`、`owner.name`，确认官方账号身份。
3. **尝试投稿接口**：优先用 UP 投稿列表；若返回风控/412/-352，不要卡住。
4. **搜索接口 fallback**：按以下组合搜索并翻页：
   - `<UP主名>`
   - `<UP主名> 高中物理`
   - `<UP主名> 具体专题`，如 `单棒 电磁感应`、`雅礼 物理`
   - 旧账号/别名，如 `UP-乙不美不物理`、`林婉晴 UP-乙 高中物理`
5. **逐条详情核验**：对候选 BV 调 `video_detail`，核对：`owner.mid/name`、发布时间、时长、分 P、标题、简介、版权。
6. **按知识点缺口排序，而不是只按播放量/新旧排序**：先用本地 `raw/transcripts/` 与 `LLMWiki/concepts/视频-*` 建立已有覆盖基线；再把候选按物理模块/题型归类（如动量守恒、圆周运动、磁场轨迹、变压器、热学气缸、静电场、电磁感应含容导棒等）。优先推荐“高教学价值 + 库中尚未补齐或只有零散覆盖”的视频；对已覆盖主题标注“同主题补充/高重复”。
7. **筛选导入优先级**：
   - 高：新课讲解、题目讲解、解题方法/题型归纳，官方账号，未导入，且补知识库空白或薄弱点。
   - 中：专题补充、期末/高考复习串讲，内容明确但可能较长；或与已有视频同主题但讲法/题型明显互补。
   - 低/默认不导入：学习规划、直播回放、娱乐/采访、搬运合集、付费课合集、非官方录屏，除非用户明确要求。
8. **处理同一教师多账号/近似账号**：例如UP-甲可能同时出现 `教物理的UP-甲` 与 `只教物理的UP-甲`，必须分别记录 `owner.mid/name`、BV、发布时间与导入状态；不要仅凭昵称合并，也不要因账号名相近就误判重复。若用户关注的是教师而非账号，可把两账号候选并列表达，并标注“需用户确认是否同一关注范围”。
9. **输出候选审计**：保存到 `LLMWiki/_meta/` 或本次任务状态目录，列出已导入清单、抓取失败原因、候选表、默认不导入原因、知识点缺口判断、推荐导入顺序。
10. **等待用户确认再导入**：候选发现阶段不下载、不转写、不改 raw/Wiki/RAG。若当前对话是总控对话，尤其只做筛选、排序、把关；不要因为找到了高优先级候选就自动启动导入。

## 候选表字段

建议字段：

| 优先级 | 标题 | BV号 | 发布时间 | 时长 | 作者/owner.mid | 知识点/题型 | 本地覆盖情况 | 判断 |
|---|---|---|---|---:|---|---|---|---|

对默认不导入项也要列原因，避免下次重复判断。

## 注意事项

- 风控失败本身不是持久规则；持久规则是：**投稿列表失败时改用搜索 + video_detail 组合验证**。
- 不要把非官方搬运、直播回放、付费课合集混入正式导入候选。
- 对“新账号”或同名/近似名 UP 主，必须用 `owner.mid` 和用户确认来判定是否纳入关注范围。
- 若用户问“怎么没触发压缩上下文”，不要把这当成导入指令；只解释压缩由系统按上下文预算自动触发，工具结果不一定完整进入主上下文，`[Your active task list was preserved across context compression]` 表示已经发生过压缩。随后回到候选发现/排序任务。
- 总控对话做候选发现时，搜索结果可能很长；优先把中间发现写成候选审计/任务状态文件，再给用户短结论，避免把大批原始搜索结果塞进主上下文。
